## 2. 前台：样式固定，内容全是接口

弹层 `width: min(1080px, calc(100vw - 28px))`。四页签不变：订阅 | 容量 | 积分 | 明细。

### 2.1 订阅页结构（抄参考稿）

- 顶栏：订阅中心 + 身份（未开通 / VIP · 到期 / SVIP · 到期）+ 右上角积分和容量摘要。
- 未完成订单条 +「继续支付」。
- 居中 **月卡 / 季卡 / 年卡**。省钱百分比用月卡价现场算，算不出来或更贵就不显示。
- 三列：**未开通** | 当前周期 VIP 商品 | 当前周期 SVIP 商品。
- 每张卡固定区块：标题、角标、现价、划线价、日均、礼包条、套餐对照表、对勾清单、按钮。
- VIP 蓝紫顶、SVIP 金棕顶。按钮颜色按档。
- 页脚一句：清单只展示，入口不上锁。

窄屏三列改单列。支付渠道只渲染后台已启用且配置完成的插件。兑换码只放容量页和积分页。

### 2.2 卡上每一格从哪来

| 格子 | 来源 | 前台不许写死 |
| --- | --- | --- |
| 名称、角标、强调 | 商品 `name` / `badge` / `highlighted` | ✓ |
| 现价、划线价 | `amountFen` / `originalAmountFen` | ✓ |
| 日均 | 现价 ÷ `durationDays` | ✓ |
| 礼包条「开通赠送 x 积分 · 套餐容量 y」 | `creditsMicrocredits`、`storageQuotaBytes` | ✓ |
| 对照：平台功能入口 | 商品 `entryLabel`；未开通读免费配置 | ✓ |
| 对照：云存储 | 该商品容量；未开通读平台默认配额 | ✓ |
| 对照：开通礼包 | 该商品积分；未开通「—」 | ✓ |
| 对照：容量加购 | 商品 `addOnLabel`，种子「可叠加」/ 免费「可买，不加会员」 | ✓ |
| 对照：适合谁 | 商品 `audience` | ✓ |
| 底部对勾清单 | 商品 `featureLines[]`：`{ text, included }` | ✓ |
| 未开通整列 | 站点配置 `membershipFreeShowcase` | ✓ |
| 按钮可点与否 | 现网购买资格，不看清单打勾 | — |

未开通列没有 SKU、不能买。已开通时，当前档按钮改成「当前方案」或「续费」，资格仍走 30 天窗口和「SVIP 不能买 VIP」。

### 2.3 容量页 / 积分页

样式抄参考稿四格卡。内容仍读上架商品。

容量卡额外展示 **有效期**（读 `durationDays`，默认「1 年」）。导语改成：加购按商品有效期计入，到期失效，不改变会员档位。

启用个人桶时：容量条仍只显示个人已用；云加购仍可买，到期规则一样，但不进当前容量条。

积分包继续长期有效，不套用容量年期。

### 2.4 明细页

继续用现有积分流水。不要拼假的「订阅 / 容量 / 积分」混合表。标题用「积分明细」。

## 3. 后台：改了前台立刻变

### 3.1 订阅商品（六张 SKU，不能新增种类）

现有字段照旧：名称、说明、售价、划线价、赠送积分、套餐容量、角标、强调、排序、上下架。SKU、档位、时长仍不能改。

新增可编辑：

| 字段 | 含义 | 限制 |
| --- | --- | --- |
| 平台功能入口 | 对照表那一行 | ≤ 40 字 |
| 适合谁 | 对照表那一行 | ≤ 40 字 |
| 容量加购文案 | 对照表那一行 | ≤ 40 字 |
| 功能清单 | 有序列表，每条「文案 + 包含/不包含」 | 最多 12 条，每条 ≤ 40 字 |

抽屉保留「只影响之后的新订单」说明，但范围是价 / 积分 / 容量。**功能清单、入口文案、适合谁改完，打开钱包立刻变**（只是展示，不进订单快照）。

同档月/季/年清单容易改散。抽屉提供 **「同步到同档其他周期」**：把当前 SKU 的入口文案、适合谁、加购文案、功能清单拷到同 `tier` 的另外两张卡。价和积分不同步。

### 3.2 未开通展示

支付页加一块「未开通 / 免费列」，不是第七种会员，不能买。

可改：标题（种子「免费使用」）、副文案、平台功能入口、适合谁、加购文案、功能清单。云存储那一行仍读运行策略默认配额，不在这里填 GiB。

### 3.3 容量商品

现有：名称、说明、价格、加购 GiB、角标、上下架。

新增：**有效天数**，整数，默认 **365**，范围 1–3650。前台显示「1 年」或「N 天」。

积分商品不加有效期。

### 3.4 容量兑换码

建批次时加有效天数，默认 365。兑成功按批次天数写授予。不填或 0 按 365。

## 5. 容量年期：真会少配额

现网 `user_membership.storage_bonus_bytes` 是一笔整数，支付/兑换直接累加，**永不过期**。这和「默认 1 年」冲突，要改数据模型。

### 5.1 新表 `storage_grants`

一笔加购一行：

- 用户、字节数、来源（支付 / 兑换 / 管理员 / 迁移回填）
- 订单号或兑换码（可空）
- 开始时间、**到期时间**
- 商品 ID、备注

有效加购 = `SUM(bytes) WHERE ends_at > now()`。  
解析配额时：平台默认或套餐容量 + **当前仍有效的加购之和**，仍封顶 3TiB。

`storage_bonus_bytes` 改成缓存，每次授予或读配额时按有效授予重算，避免后台列表和真实配额打架。

多笔各自到期。例如 1 月买 20 GiB、6 月买 50 GiB，明年 1 月掉 20、6 月再掉 50。

到期：**只减配额，不删文件、不改会员档。** 已用超过新配额时，不能再往平台桶传，直到删文件或再买。个人桶不受这笔云配额约束（现网已跳过）。

### 5.2 下单快照

容量订单除现有 `storageQuotaBytes`，再快照 **有效天数**。支付成功按快照起算到期，之后后台改商品天数不影响这张单。

会员套餐容量仍是覆盖 `planStorageQuotaBytes`，跟会员到期走，不是加购年期。

### 5.3 已买过的加购

v1.5.64 文案写过「不过期」。迁移时：若用户已有 `storage_bonus_bytes > 0`，回填 **一条到期时间为空的授予**（视为永久）。新买的才默认 1 年。

不要把旧加购强行改成从迁移日起再给 1 年——等于收回已售承诺。

### 5.4 前台怎么说

- 容量卡：「有效期 1 年」（或后台设的天数）
- 导语：到期自动失效，可叠加多笔
- 可选：摘要「加购剩余 x GiB，最早 yyyy-mm-dd 到期」
- 删掉所有「不过期 / 永久扩容」文案

不做定时扫表删行。读配额时按 `ends_at` 过滤即可。

后台：

- 更新会员商品：现有价/积分/容量 + 清单四件套；可选 `syncShowcaseToTier: true`
- 读写 `membershipFreeShowcase`
- 更新/新建容量商品含 `durationDays`
